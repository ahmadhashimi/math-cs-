Logarithms

The single most useful function in computer science, and the one almost everybody skipped.

Why a CS
major needs this

Every time you halve a problem instead of walking through it, a logarithm shows up in the running time. Binary search, balanced trees, merge sort, heap operations, the depth of a divide-and-conquer recursion are all O(log n). Understand what a logarithm counts and you can read those running times straight off the algorithm.

A logarithm asks a counting question: how many times do I multiply the base by itself to get here?

Definition
logb(x) = y ⟺ by = x
Same fact, two directions.
Product rule
log(xy) = log x + log y
Multiplication becomes addition.
Change of base
logbx = ln x / ln b
Why Big-O ignores the base.

Check yourself

A sorted array holds 1,048,576 records. What is the worst-case number of comparisons a binary search makes?

{{ verdict }}

Each comparison throws away half the array, so the count is how many halvings reduce 1,048,576 to 1: log₂(1,048,576) = 20, because 2²⁰ = 1,048,576. A linear scan would take up to a million comparisons for the same answer.
